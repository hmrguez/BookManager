# Reading original files

Native EPUB, PDF, and audiobook imports retain access to the selected original. Wovenleaf does not create a full private content copy. Generated covers, metadata, annotations, reading checkpoints, and engine caches remain local to the app. Keep originals downloaded in Files or the Android document provider for offline use.

Opening checks the saved reference, readability, size where applicable, and content fingerprint. Missing files, lost access, offline iCloud files, changed contents, and unsupported providers produce recovery messages. **Choose file** repairs an exact match without replacing asset IDs, audiobook capability IDs, reading positions, bookmarks, or notes. Selecting changed contents follows the existing explicit import/revision flow.

The file picker uses iOS open-in-place bookmarks or Android persisted document/tree grants. An absolute path alone is insufficient on these systems. JavaScript and native playback snapshots exchange opaque `wovenleaf-file://` references; the OS locator stays in a device-local native registry. iOS retains coordinated security-scoped access for a reader or loaded audio queue. Android readers and playback consume the provider URI/descriptor directly. PDFs require a seekable Android descriptor and fail with local-download guidance when a provider cannot supply one.

Book/audio Open With and share intake intercept sources before Wovenleaf's generic copying path. Android opens readable content URIs immediately, including the temporary read grants supplied by Files by Google. It persists grants when the sender offers that capability, but never requires persistence to open a currently readable file. Each later open checks the provider again; if access has expired, **Choose file** restores access through the document picker. An Android temporary grant may end with the receiving task or a reboot, so it does not promise permanent access. iOS temporary-only representations and native HTML/drop inputs without an original reference still require reselection. CSV sharing and browser imports retain their existing behavior.

## Storage and compatibility

- New ebook content assets use `linked-file`; audio content assets use `linked-bundle` with a reference for every segment. Migration 18 adds nullable `audiobook_files.reference_id`. Existing managed paths remain unchanged; linked rows use the reference and an empty legacy path column.
- Existing private imports remain readable. Wovenleaf cannot recover their original locations automatically. Exact ebook relinking retains the old private path for explicit storage cleanup. Existing private audiobook bytes are also retained when relinked; this change does not add an audiobook storage-cleanup UI.
- Cleanup validates app ownership and rejects original paths, including stale or forged previews. It never deletes or overwrites external content. Book content accounting separates linked bytes from private content copies.
- Portable archives omit device-local references. Optional EPUB/PDF inclusion reads the original explicitly and verifies its hash; unavailable active originals prevent an incomplete file-inclusive export. Audio byte backups are unchanged and outside this feature.
- Registry reconciliation follows storage migration/recovery. It retains catalog references and active/native audio consumers, with a one-day grace period for unfinished picks and extension handoffs. Releasing abandoned references never removes the source file.
- Native EPUB and audio selections retain a reference without constructing a full JavaScript file payload. EPUB inspection reads the ZIP directory and selected publication resources; M4B inspection reads container metadata while seeking over audio; MP3 inspection reads ID3 metadata and an audio prefix, with duration supplied by the native media framework. Covers and small sidecars still need their own byte buffers. Browser imports and PDF metadata inspection still read full bytes in memory.
- SHA-256 identity is streamed natively from the original. Android reuses fingerprints within the process only while descriptor identity, size, modification time, and high-resolution change time match. Every check still opens the provider descriptor and validates access. Coarse timestamps, non-regular sources, process restarts, and changed originals require a fresh hash. Existing archive/file-count limits remain, including the 256 MiB EPUB limit.

## Verification, 2026-09-20

`bun run lint`, `bun run typecheck`, and all 355 Bun tests pass. Coverage includes linked EPUB/PDF import and native capability construction, no content writes, changed originals, exact relinking, original cleanup protection, retained private-copy cleanup, portable reference stripping, included ebook bytes, missing audio segments, per-track identity preservation, reopening completed audio after relinking, and migration of existing managed audio.

Both native Debug builds pass. Android's Open With instrumentation covers direct EPUB/PDF opening, audio review and reopening, repeated handoffs without duplicate imports, large-file feedback, missing originals, and no private content copies. Bridge checks exercise integer chunk offsets and byte-size validation: Capacitor's `getLong` accepts only boxed `Long`, whereas JSON delivers ordinary book sizes and the first read's zero offset as `Integer`. Both numeric representations must be accepted. Picker error layout is checked in the device WebView so an inline error cannot compress its action label.

The complete Open With instrumentation passed on a connected **Pixel 9, Android 17 (API 37)**. Through Android Studio's device mirror, Files by Google opened generated EPUB and PDF files directly in the native readers and an MP3 directly in the player; the audio played to completion. These handoffs saved three `com.google.android.apps.nbu.files.provider` references without requiring a second selection. The native document picker's existing persisted grants remain supported. Temporary read access follows [Android's activity-stack lifetime](https://developer.android.com/reference/androidx/core/content/FileProvider); durable access still requires a grant offered by the provider.

Device verification also exposed a completed-audiobook recovery defect: the queue validator rejected an initial position equal to its duration. The end position is now valid, preserving 100% when an original is reopened/relinked; positions beyond the duration remain invalid. Android Play seeks to the beginning when replaying a completed queue. Idle playback no longer advances its revision every 500 ms, preventing unchanged completed/error queues from racing a fresh Open With command. A content-hash audit of the app's files and cache found no full copies of the generated external originals outside the instrumentation fixture directory.

On the dedicated **Wovenleaf Original Files** iPhone 17 Pro simulator (iOS 26.5), generated fixtures were placed in the Files local provider outside Wovenleaf's container. The real native picker imported EPUB and PDF originals. Readium rendered the EPUB and persisted a bookmark; PDFKit turned pages. Removing the PDF produced recovery, and selecting identical bytes under another filename resumed on page 2 with the same asset identity. A real AAC M4B loaded from its original, played to completion in the background, replayed, and sought/paused at 51%. Two original MP3 files were selected together, imported as a linked bundle, and played across their boundary to the second segment’s end. Removing the M4B and selecting its identical replacement restored 51% with unchanged queue/segment/capability identities. Native reference access survived app relaunch and application-container relocation during reinstall. After a full simulator reboot, the final build reopened the original EPUB with its existing bookmark. SQLite and private storage inspection confirmed linked records and no full EPUB/PDF/audio content files; only the generated PDF cover was stored privately.

Files shared a 10.8 MB generated PDF through the iOS extension. Its payload contained an original reference; returning to Wovenleaf consumed that handoff and opened PDFKit. A content-hash audit of the complete app data container found no copies of any test original, and the shared `IncomingShares` directory contained no book/audio files.

The simulator exposed and verified a fix for an AVQueuePlayer completion crash: its temporary indefinite time is now guarded before integer conversion, and completed queues can be replayed.

Physical-device calls, Bluetooth, long-running locked playback, cloud/provider-offline behavior, stale bookmarks, and Android provider seekability still require the existing release device matrix. Provider-owned downloads and caches are outside Wovenleaf's storage ownership.

## Large-original verification, 2026-09-20

The connected Pixel 9 ran an updated Debug build through Files by Google → Open with Wovenleaf. Measurements below are individual verification runs, including the Android handoff; they are not benchmark averages. Audio readiness comes from the native loaded-queue snapshot; EPUB readiness comes from the first rendered-location event. Screenshots confirmed the corresponding player/pages.

| Original | Size (decimal) | First measured open | Warm reopen | JavaScript inspection reads per open |
| --- | ---: | ---: | ---: | ---: |
| AAC M4B derived from local video audio | 595.0 MB | 4.6 s after process start | 3.0 s | 6.74 MB of container metadata/header ranges |
| Generated illustrated EPUB, 130 chapters/260 images | 202.0 MB | 8.4 s | 7.1 s | 190 KB in 270 range requests |
| Existing illustrated EPUB, *El Imperio Final* | 11.1 MB | 4.5 s | 5.2 s | 800 KB in 64 range requests, including cover/text |

The M4B was produced by remuxing the audio track of an existing local video, then repeating that audio six times without re-encoding to exceed 500 MB. The original video was unchanged. The stress EPUB repeated an existing illustration in a valid EPUB 3 package; its image payloads remain in the original ZIP. Generated files live in `Download/Wovenleaf-Verification` on the test phone, outside app storage, and are not repository fixtures.

Before this optimization, the same M4B made 568 full-content bridge reads over 79 seconds and failed after about 85 seconds with a false DRM error. The old detector matched the bytes `sinf` inside ordinary compressed audio. Protection and codec checks now parse actual MPEG-4 sample-description atoms; compressed audio and artwork cannot trigger that false match.

Audio playback, seeking to 75%, pausing, and reopening at the saved position passed. The large EPUB rendered illustrations, navigated to 70%, and restored the same page after reopening. The real EPUB rendered its cover and chapter text and restored its position at 49%. A private files/cache audit found no large audiobook or EPUB copies; its only file over 10 MB was the existing generated PDF instrumentation fixture.

The full Android Open With instrumentation passes, including same-size source mutation invalidating the fingerprint cache, missing files, duplicate handoffs, and playback completion. A delayed play response discovered during testing can no longer overwrite a newer completion snapshot; Android reports the canonical duration at the end of the queue. The iOS simulator Debug build also passes with the native audio-duration method. `bun run lint`, `bun run typecheck`, and all 367 Bun tests pass, including range-inspection equivalence, ZIP safety checks, a virtual 600 MB M4B with metadata after its payload, MP3 inspection, structural DRM detection, and delayed playback responses.

No private full-content copy or full JavaScript preload is required for native EPUB/audio intake. Opening still includes provider access, initial native fingerprinting, metadata inspection, and reader startup/layout. In particular, a chapter-heavy EPUB makes multiple small metadata reads and takes several seconds even when its large image payloads are skipped.
